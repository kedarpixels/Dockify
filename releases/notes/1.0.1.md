## 1.0.1 (2026-11-07)

Rename apps, a fuller view of apps that follow Vercel, and fixes for Vercel logs and Cloudflare tokens.

### Added
- Rename an app. Settings has a Name section for the name the dashboard, notifications, emails and pull request comments show. The app's original name stays its identity for containers, volumes, links, preview hosts and the CLI, so nothing is redeployed. Two apps in one environment cannot show the same name.
- An app that follows Vercel now reads its Vercel project live. Overview shows what production serves (domains, commit, branch, author, build time) and the project settings, Variables lists the project's environment variables (an admin sees plain values, encrypted and sensitive values are never shown), and Domains lists the project's domains on Vercel. Each tab links to manage it on Vercel.

### Changed
- Counts in group headings are in brackets, so a count after a date, as in "Sat 7 Nov (19)", no longer reads as part of it.

### Fixed
- The Logs tab of an app that follows Vercel could keep showing "Too many log reads" after you switched tabs, because a read for a page you had left kept its slot. A read now stops the moment you leave, and the tab says plainly when Vercel has no runtime logs.
- Connecting a Cloudflare token with only zone permissions failed with "This token cannot see any Cloudflare account". Dockify now takes the account from the token's zones.
- After `install.sh --upgrade` from the signed feed, Settings, Updates could still ask to set DOCKIFY_RELEASE_FEED on an install made without a feed. The upgrade now records the feed and key that checked the new images in `.env`.
