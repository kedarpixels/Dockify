## 1.0.3 (2026-11-08)

Project icons start as the folder, the version is right after an in-app update, and the local backup warning says what to do.

### Changed
- A project's icon is now the folder unless you choose otherwise. The Icon dropdown offers Folder (the default), each frontend with a fetched favicon, and the uploaded image while there is one. Automatic is gone: a project on Automatic shows the folder after the update, and a project set to an app's favicon or to an upload keeps it. If the chosen app is deleted or loses its favicon, the project shows the folder. Apps still fetch their favicons as before.

### Fixed
- After an in-app update, the version some places read stayed at the version first installed, because the updater rewrites only `release/release.env` and `.env` kept the old `DOCKIFY_VERSION`. Dockify now reads the version baked into the image it runs, so the agent, the update checks, the update notices and Settings all name the running version. The Settings menu now shows the version too; it showed none before.
- The "On this server" backup tier said to add S3 compatible storage even when storage was set up and the Offsite tier was on. The warning now shows only while a database's copies stay on this server, and says to turn on the Offsite tier when storage exists, or to add storage first when it does not.
