## 1.0.5 (2026-11-11)

1.0.4 was tagged but its build never published, so this release carries its changes. A security and reliability release: two-factor codes can no longer be guessed over time, a tenant can no longer stall or crash the worker, and the dashboard keeps up with what the server holds. Three database migrations run on update.

### Security
- Two-factor codes share one limit per account across sign in, step-up and turning two-factor off. Ten wrong codes lock the account for 15 minutes, each lockout in a row doubles (up to 24 hours), the count survives restarts and updates, and the account's owner gets an email on the first lockout.
- Previews are kept per repository and pull request. Two repositories in one project no longer share a preview, so closing a pull request in one can never tear down the other's. Whether a preview builds a fork's commit is fixed when the build is queued.
- Build output in a failed deploy notice can no longer carry a live link to chat or email.
- Viewers and read tokens no longer see Vercel build and install commands, backup destinations, bucket names, provider errors or the backup key fingerprint. Project-limited tokens no longer see the owner's email.
- Dockify's own update dump can no longer be downloaded, restored or swept as an orphaned backup.
- Status page feeds ignore a forwarded host sent by the client.
- The container firewall rules now load before Docker starts after a reboot. Uninstall removes the new unit.
- A rollback to the previous release is trusted only within the rollback window.
- Images whose labels exceed 64 KB are refused before a container is created.

### Fixed
- A tenant database could crash the worker through the data browser, or stall every project's backups by holding a lock. Data jobs now have deadlines, pg_dump waits at most 5 minutes for a lock, dumps respect backpressure, and the data browser and SQL console read within fixed bounds. The SQL console runs one statement per request.
- Restore downloads stop at the backup's recorded size. Restore errors no longer include table rows.
- Sites that declare only an SVG icon now get their favicon: it is sanitized and served like an SVG logo. Emails and pull request comments show the default icon for those.
- A favicon that is missing now says so ("/favicon.ico answered 404") instead of reporting a size or format error.
- Notifications are ordered by time, "Mark as read" sticks with several tabs open, and the update notice no longer shows for the version already running.
- The Variables tables keep every key on one line, with the lock beside it.
- After adding or removing an environment, the Variables tab shows that environment's variables.
- Saving a build branch or image no longer jumps back to the old value.
- The sidebar, the command menu and the tab title follow the server on every page. Project pages, the Deployments filter, Domains, Resources, Activity and the Settings lists refresh after a change.
- Saving the Notifications settings no longer pins the preview domain as custom. Each settings section saves only its own fields.
- The Backups page reads the last 30 days by date, and a bulk backup that starts nothing says so.
- Alert history says 90 days, as it shows. A webhook test that never reached the endpoint no longer marks the webhook failing.

### Changed
- The theme toggle no longer plays a sound.
