## 1.0.6 (2026-11-12)

GitHub shows a status per app, and a new domain starts routing right away instead of waiting for builds.

### Changed
- Each app built from a commit now posts its own GitHub commit status, "Dockify / <app>" (with the environment in a project that has several), instead of one shared "Dockify" status. It shows pending while the deployment is queued, building or deploying, then Deployed, the failure reason, or Cancelled. Before, the first app to finish marked the whole commit Deployed while the others were still building, and a later success could hide an earlier failure. A branch protection rule that requires the old "Dockify" check needs the new per-app names.

### Fixed
- A domain added to an app, or an app stopped or started, waited for every queued build on the server before its route changed, so a new domain could answer "404 page not found" for minutes. Route changes now run on the maintenance queue, and a per-app lock keeps them from ever interleaving with that app's own deploy. A deploy also re-reads the app's domains when it switches traffic, so a domain added during a long build is kept.
